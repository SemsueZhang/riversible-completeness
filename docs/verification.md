# 验证方法与覆盖范围

现有测试针对 FL2025 和 FXL2026 的二值实现。它们在性能计时之外枚举状态，检查语义与范式；没有为 NF/DC 提供同等范围的回归测试。

## 基础验证

```sh
make build/verify_binary
build/verify_binary
```

`tests/verify_binary.cpp` 包含 1～4 线路的全部合法单门、空电路和固定种子的 12 门电路，共 242 个输入，每种方法分别运行。测试枚举每个输入的全部二值状态，独立按位模拟输入、路径化输出和最终范式，并与函数表插入构造的规范字比较。

程序向标准输出打印输入标识、线路数、方法、规则总数和范式摘要；失败时返回非零退出码。

## 扩展与存储分支

```sh
make verify
```

该目标先运行 `build/verify_binary --extended`，共检查 257 个输入，再运行 `tests/verify_sparse_path.cpp`。扩展输入包括 5～7 线路低目标全控制短电路，以及跨越 64 / 4096 位索引边界的抵消字。稀疏索引检查使用 11 线路、150,000 个相同路径门，要求输出为空并恰好计 75,000 次取消。

FL 坐标选择另有独立组合检查：

```sh
python3 tests/check_fl_coordinates.py
```

它枚举固定反射 Gray 路径上 1～7 线路的 769 个全控制门，仅检查坐标删除和简单链前提，不检查基本规则展开和计数。

## 结论边界

有限状态检查可以发现样本中的语义、规范端点和存储实现错误，不能代替全部输入的正确性证明。生产程序只保存局部起止字、规则总数和峰值，不输出完整规则证书。

FL2025 额外要求坐标对删除后保持简单边链，以满足后续 Lemma 3 的前提。现有实现没有证明任意线路数下始终存在这样的候选；无候选时会抛出错误。这是需要保留的一般性证明缺口，不能直接由原文完整性定理或有限枚举排除。
