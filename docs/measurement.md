# 规则总次数和时间

## 规则总次数

`rule_count` 是所选固定调度中基本规则的实际累加次数，采用 `uint64_t`，所有加法检查溢出。它不是复杂度上界、最终门数、宏调用数或最短推导长度。

| 方法 | 基本规则 |
|---|---|
| FL2025 | 原论文 RC Rules 1–5 |
| FXL2026 | 新论文 RC^r Rules 1–5 |
| NF | 本文 MRC^r Rules 1–8 |
| DC | 本文 MRC* Rules 1–5、9–11 |

派生步骤由可执行的局部重写模板计算成本。重复使用模板可以命中缓存，但每次使用都按完整成本加到规则总数；模板构造本身不额外重复计为一次规则。普通控制流、字比较、路径构造和函数表计算不计为规则。

归约到范式时，统计 `C -> NF(C)` 的总次数。判断相等时：

- FL/FXL/NF 分别归约 A、B；相等时两侧归约次数之和就是 `A -> NF -> B` 的次数。
- DC 统计两侧路径化、恒等字直接消去，以及成功连接 `A -> B` 所需的 `|B'|` 次配对插入。
- 若判为不相等，则统计完成该拒绝判断前的规则数。这不是等价推导的长度。
- 若未完成，不输出部分次数冒充完整结果。`rule_count` 留空。

不同规则系统的单个基本步骤表达能力不同。特别是 FL 原 Rule 5 是较强的模式规则，DC 的路径 braid 是基本规则，而 NF/FXL 要展开它。比较应写为“指定规则系统和调度下的基本规则总数”，不能解释为相同硬件成本。

## 时间

使用 `std::chrono::steady_clock` 的毫秒数。

计时从新建本次算法预算之前开始，至算法函数返回为止，包括：Gray 路径建立、局部模板构造和缓存、路由、规则计数、范式构造或判等、相关对象清理。DC 的范式适配还包括函数表和目标范式的构造。

不包括输入文件读取、CSV 输出、数据生成、编译、网络下载和任何独立正确性验证。没有预热、没有隐藏的穷举预判、没有在不同样本或重复之间共享算法缓存。

默认的 `target-frequency` 线路排序将目标次数统计、排序、校验及线路重映射计入 `time_ms`。它是坐标预处理，因此不增加 `rule_count`。每个输入的各种方法与重复使用同一排列；判等时合并两侧频次，生成一个共同排列。该排序只最小化输入门的目标下标之和，不搜索归约规则数或耗时最优的排列。排序后的结果与 `--wire-order original` 的原始顺序结果应分别标注。

程序按清单逐项、按方法顺序执行；不并行运行基准。`--repeat` 每次产生独立一行，不自动取平均或生成额外统计。

## 状态

- `ok`：算法完成。归约任务的 `equal` 留空，判等任务为 `true/false`。
- `not_applicable`：多值输入选择了二值方法；次数为空，时间为 0。
- `input_error`：无法读取或不支持输入，次数为空，时间为 0。
- `resource_limit`：达到时间、状态数、字长或内部工作量限制；次数为空，时间为终止前耗时。
- `error`：算法约束失败、计数溢出等错误；次数为空，不能当作不相等。
- `label_mismatch`：判等结果与清单给定的预期标签冲突；保留输出但不应纳入有效性能统计，需要另行排查。

所有失败原因写入标准错误。只要有错误或标签冲突，程序最终返回退出码 2；命令行错误返回 1。仅完成和不适用行返回 0。

默认资源限制用于约束执行规模，不代表算法理论能力。时间限制采用协作式检查，不能保证中断正在进行的内存分配；实际内存随当前电路字和模板缓存增长。当前实现不提供完整规则证书回放；测试覆盖范围见[验证说明](verification.md)。
