# FL / FXL 原文核对与实现优化

日期：2026-10-22。直接修改当前 C++ 实现；没有以真值表合成替换被测归约算法，没有把派生规则改计为一步，也没有缩减数据集。

## 原文对应与边界

核对版本为 [FL arXiv:2508.17273v2](https://arxiv.org/abs/2508.17273v2) 的 Rules 1–5、派生 Rules 6–10、Lemmas 1–5、Proposition 3、Theorem 2，以及 [FXL arXiv:2607.19059v1](https://arxiv.org/abs/2607.19059v1) 的 Section III / Algorithms 1–4。阅读了原文公式、伪代码和规则图；文献哈希见 [source-snapshot.md](source-snapshot.md)。

- FL 保留 Theorem 2 的整体补全控制、指定 Hamilton 子路径回文、坐标对删除、多元素 Rule 5，以及 Proposition 3 的独立块消去。未替换为网格运输或真值表插入排序。
- FXL 保留 Algorithm 1 的逐轮替换、X 门 Gray 次序展开和辅助 X 化简，以及 Algorithms 2–4 的最左重写位置优先级。现在按原文显式建立新一轮 C'，而不是在 C 中逐项插入并移动尾部。
- 两种方法的基本规则系统不同。派生模板的计数仍展开到各自基本规则；缓存命中仍加入完整模板成本。
- 原文没有固定所有派生证明的逐条展开顺序。当前的极性调整、补全控制和局部证明调度是明确的确定性实现，不声称是作者软件、唯一原文计数或最少规则数。

FL 另有需要明确的选择：原文允许任取合法重复坐标对，并描述删除后的相邻重复坐标清理；当前代码只选删除后仍为简单边链的候选，因此不会进入那条清理分支。这是对论文未固定选择的限制，不能隐去。本次保持该选择，没有把可能违反 Lemma 3 前提的坐标对强行加入。`tests/check_fl_coordinates.py` 对固定反射 Gray 路径上 1～7 线路的全部 **769 个全控制门**检查了这一选择，均能缩减到目标坐标。该检查只验证坐标选择和简单链前提，不是完整规则推导验证，也不证明任意 n 或任意 Hamilton 路径均可采用该限制。

## 修复的额外开销

| 位置 | 原实现 | 当前实现 | 是否改变规则数 / 顺序 |
|---|---|---|---|
| `src/core.cpp` | 每次替换都 erase + insert；等长替换也移动整个尾部 | 等长替换原位覆盖，变长替换只移动尾部一次；基本 edit 不再分配共享摘要对象 | 不改变 |
| `src/compiler.cpp` | 相邻交换构造多份临时门数组；删除辅助分支逐步交换并移动尾部 | 合法基本交换原位执行；检查同一串 Rule 3 交叉条件后，直接累加原交换和取消总数并删除端点 | 不改变 |
| `src/fxl2026.cpp` | 每轮复制旧电路，并逐门在旧电路中插入替换字 | 移走旧轮，只按顺序追加构造新轮；仍保留原有轮次和化简位置 | 不改变 |
| `src/indexed_path.cpp` | 每次局部改写后从头扫描电路、用完整门对象查路径下标 | 当前门用整数编号表示；维护存活链、出现位置、可改写位置和递增链断点 | 不改变最左选择与 FL/FXL 各自调度 |
| `src/experiments.cpp` | 范式归约完成后，为组合总数再次复制和应用两个完整阶段 | 对已完成且端点衔接的两个阶段直接求总数和 | 不改变 |

特别地，旧版 FXL Algorithm 3 的最左改写点搜索每次可能扫描整个当前字；新的位置索引直接定位相同的位置。紧凑模式的查询/更新按分层位图执行，层数约为 `log_64 L`，不再附带每次 `O(L)` 的扫描。当前字的局部删除也只更新链指针，不搬移后缀。该优化降低的是实现附加复杂度，没有减少算法选择执行的规则。

## 空间处理

不保存逐步推导历史或完整证书。范式阶段只保留当前字的整数标签、存活链和位置索引；不会把每次交换后的字另存一份。被删除位置保留空槽，空间受初始路径字长度约束，不随重写次数增长。

局部模板缓存每个实例最多保存合计 65,536 个端点门（也不超过 max_word）；单个摘要超过 4,096 个端点门就不缓存。大型路径化结果只由当前调用持有。缓存键改为固定宽度二进制编码，避免字符串流格式化。

出现位置索引的稠密位图超过约 32 MiB 规模时改用稀疏位置集合，避免较大状态空间导致乘积空间分配。仍需保留算法正在处理的当前路径字和必要端点，因此不保存历史不意味着当前状态可以无限增大。`max_word` 仍限制真实当前状态和局部证明峰值。

## 验证

- `tests/verify_binary.cpp`：1～4 线路的全部单门（允许无控制、正控制、负控制）、空电路和固定种子的短电路，共 242 个；两种方法共 484 条规则总数和最终范式摘要，与修改前版本逐项完全一致。
- 扩展验证共 257 个电路：另外包括 5～7 线路低目标全控制短电路，以及跨越 64 / 4096 位索引边界的长抵消字。逐输入枚举全部二值状态，独立按位模拟输入、路径化输出、最终范式；另与真值表插入构造的规范字比较。真值表只作为计时外的验证工具，未进入 FL/FXL。
- 242 个基础电路通过 AddressSanitizer / UndefinedBehaviorSanitizer 检查。
- `tests/verify_sparse_path.cpp`：11 线路、150,000 个相同路径门触发稀疏位置索引，两种方法均得到空字与精确 75,000 次取消。该用例验证存储分支，不作为性能数据集。
- 较高目标的扩展验证尝试曾触及原 200,000 字长保护，属于资源未完成；最终固定验证套件使用明确受限的低目标高线路样本。大规模高目标情况由公开数据集单独计时并如实报告资源超限，不将未完成项算作通过验证。
- 本次公开集重测中，对旧版和新版都完成的 84 条记录逐条核对基本规则数，完全一致。性能比较使用相同电路的完整成功结果。

复现基础验证：先 `make -j4`，再编译测试入口（不自动运行基准）：

```sh
c++ -O2 -std=c++17 -Iinclude tests/verify_binary.cpp \
  build/core.o build/compiler.o build/routing.o build/path.o \
  build/indexed_path.o build/fl2025.o build/fxl2026.o build/nf.o build/dc.o \
  -o build/verify_binary
build/verify_binary --extended
python3 tests/check_fl_coordinates.py
```

这仍不是逐实例完整规则证书回放，也不是全部输入的正确性证明。性能报告见 [优化后重测](../results/fl-fxl-optimized-20261022/report.md)。
